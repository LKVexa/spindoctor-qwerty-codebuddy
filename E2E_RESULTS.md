# End-to-end results: spindoctor-qwerty-codebuddy 1.1.0

Run on 2026-10-10 (PT) in a clean-room copy (empty folder, empty HOME, PATH=/usr/bin:/bin, no access to engine development
folders), following only this README: marketplace add + install with the CodeBuddy CLI, then `tests/codebuddy_host_check.py`.

**Mode:** real host, tool calls host-simulated. **CodeBuddy Code 2.164.0** was installed from npm (`npm i
@tencent-ai/codebuddy-code`) on a Linux test machine and used with no account, no sign-in and no model calls. It validated the
marketplace and plugin manifests, added the marketplace, installed `spindoctor-qwerty@spindoctor-qwerty-codebuddy`, listed it
enabled at 1.1.0 with every component in its plugin cache, disabled and re-enabled it, and uninstalled it. CodeBuddy has no
command that lists a plugin's MCP servers outside a session, and starting a session needs a login (ACP `initialize` works, but
`session/new` answers "Authentication required"), so `tests/e2e_mcp.py` drove the MCP server from CodeBuddy's installed copy,
started exactly as `.mcp.json` declares (`${CODEBUDDY_PLUGIN_ROOT}` and `${CODEBUDDY_PLUGIN_DATA}` substituted and exported, as
the plugin reference documents).

**Format check:** the CodeBuddy plugin reference and marketplace guide (workbuddy.ai/docs/zh/cli/plugins-reference and
plugin-marketplaces, read 2026-10-10) still describe `.codebuddy-plugin/plugin.json` (or `.workbuddy-plugin/`, `.claude-plugin/`),
`.codebuddy-plugin/marketplace.json`, `commands/`, `agents/`, `skills/`, `.mcp.json` and the `${CODEBUDDY_PLUGIN_ROOT}` /
`${CODEBUDDY_PLUGIN_DATA}` variables. The codebuddy.ai copies of these pages didn't load from the test machine.

**Parity target:** the updated SpinDoctor 3.1.2. Publishing was approved by Russell on the basis of the updated 3.1.2 passing its
own suite 18/18, with the three 29-qubit test checks adapted to the 298-qubit limit.
